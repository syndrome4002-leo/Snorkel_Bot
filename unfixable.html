Describe what makes this task technically challenging. Consider factors such as edge cases, implementation dependencies, requirements that may be overlooked on first reading, or complexity in the test setup.

None of the rules are written down for the agent. They have to be recovered from the sidebar's existing Windows only walk and then survive being moved somewhere they can run with no filesystem underneath them, which is the part that turns this from a local edit into a rebuild. Once found they interact rather than stack. A dot folder stays out even when hidden items are being shown, so the dot rule cannot be folded in with the others. The system marking on its own keeps nothing out, it only matters alongside the hidden marking, which is easy to read the wrong way round. A folder that is hidden, system and dot named passes all three and only one of them decides it. The same rules then have to be applied a second time one level down, because the expander chevron is a promise that there is something to expand into, and the shipped PR got exactly this wrong by counting any directory instead of the ones the user would see. Folders that cannot be read have to be shrugged off at both levels rather than thrown, and one that cannot be read still belongs in the list, just without a chevron. On top of that the cap applies to the sorted list, so stopping the walk once enough entries have been collected looks correct on a small folder and returns the wrong entries on a large one, and ordering is by display name with case ignored rather than by path or by ordinal. Five independent things have to be right at once before any of it goes green.
