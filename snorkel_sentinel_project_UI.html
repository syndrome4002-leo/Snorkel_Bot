The provider swap looks like the work and is not. Once a snake_case naming convention is in play, every entity type carries an explicit table name annotation, and the shared kernel's own pluralization step reads that annotation and preserves it instead of pluralizing. So a change that renames every column correctly still puts the aggregate in a singular table. The model builds, the schema is created, nothing throws, and the first sign of trouble is a query naming the plural form and matching nothing. Finding it means reading the base OnModelCreating rather than the file the symptom shows up in. Around that sits the rest of the migration: package references in two files that have to move together, a dependency injection path that now builds a data source instead of passing a connection string, and a data migration runner whose exclusive lock was a SQL Server stored procedure with four negative return codes and becomes a Postgres advisory lock keyed off a hash. The fixtures are a second front. The in memory SQLite context has to take the same naming or the suite exercises a mapping the application never uses, and every raw SQL string in those tests has to move in the same pass.
